# MySQL 单体版上线检查

检查日期：2026-10-24。范围：当前工作区代码、MySQL 单体 Maven 构建、单体 CI 配置、当前主机运行配置与元数据只读检查。

结论：当前具备可运行的内部试用基线，尚不满足正式业务上线条件。已有页面、配置保存和发布状态，不代表对应运行链路已闭合。本报告没有用旧 PostgreSQL 模块的测试或上线脚本为 MySQL 单体版背书。

- `mvn -B -ntp -pl dataguard-standalone -am verify` 成功，8 个测试通过，0 失败，0 错误，0 跳过。
- 这 8 个测试来自 GuardTest、MysqlProductionGateTest、MysqlReadGrantPolicyTest 和 ReadMaskTest，覆盖工具方法及配置校验，没有覆盖 HTTP、数据库事务和新管理 API 的集成行为。

- 没有对正在使用的数据库运行会改管理员密码、创建测试用户的 HTTP 验收脚本，没有更改部署参数或业务数据。

## 上线阻塞项

### B01 SQL 策略没有进入真实读取判定

状态：功能未闭合，P1。

证据：`dataguard-standalone/.../SqlPolicyApi.java:79` 的发布只更新策略和版本状态；`:104` 的有效判定返回 `simulationOnly=true`。`ReadApi.java:57` 至 `:91` 只依据数据源、表白名单、个人审批和字段授权构造查询，没有调用 SQL 策略判定，也没有数据源环境字段供环境规则匹配。

影响：即使界面发布某张表的 DENY 规则，已满足白名单与审批的读取仍可能继续执行。当前不能把策略发布视为业务访问已被该策略阻断。

验收要求：把发布版本、环境、表、操作和优先级接入统一判定；Web 与 MCP 使用同一路径；发布 DENY 后真实读取被拒绝，停用与并发更新有明确语义；记录命中策略版本。REQUIRE_APPROVAL 的运行语义也需明确实现。

### B02 流程设计发布不会改变实际审批

状态：功能未实现，P1。

证据：`WorkflowDesignApi.java:81` 明确记录 metadata only，`:82` 返回 `flowableDeploymentEnabled=false`。`ApprovalApi.java:44` 固定启动 `internalReadApproval`，使用单个指定审批人。设计里的节点角色是字符串，没有与系统用户或实际角色绑定。

影响：多级节点、角色顺序、高风险节点选项不会影响实际审批任务；界面的“已发布”容易让使用者误以为配置已经生效。

验收要求：受控部署流程版本，申请绑定确切版本，节点映射真实用户或角色，实际任务按节点推进；验证自批禁止、越权、拒绝、过期与并发处理。已有流程实例的版本处理需要有规则。

### B03 密码变更缺少全会话撤销

状态：实现不完整，P1，基于代码路径确认，尚未进行双浏览器运行复现。

证据：`UsersApi.java:39` 仅使发起改密的当前 Session 失效；`:85` 重置密码只改密码哈希和首次改密标记。`ForcedPasswordFilter.java:25` 只核对 enabled 与 must_change_password，没有密码版本或 Session 撤销版本校验。

影响：管理员重置密码时旧会话会暂时被改密标记阻拦，但用户完成新密码设置后，其他未销毁的旧会话可能恢复业务访问。现有 token 也没有随密码事件主动撤销。

验收要求：引入用户认证版本或集中会话撤销；改密、重置、停用事件使所有相关会话永久失效；明确 Agent token 是否同步撤销并验证；完成双会话回归。

### B04 读取资源限制不足

状态：实现不完整，P1。

证据：`ReadApi.java:91` 使用 SELECT *，`:104` 至 `:113` 通过 getObject 取所有字段后才脱敏、截断并收集到内存。现有上限是 100 行和部分 JDBC 超时，没有结果总字节、字段读取字节、并发连接数、用户或 Agent 配额上限。目标连接由 DriverManager 每次创建。

影响：大 TEXT/BLOB 或宽表仍可造成高内存和目标连接压力；脱敏不等于不读取敏感字段。部分 SHOW GRANTS 阶段和整个请求也没有统一总时限。

验收要求：投影到必要列，限制字段与结果字节、请求总耗时、并发与速率；覆盖大字段、慢查询、目标断连与并发压测，超限不返回部分敏感结果。

### B05 审批和授权生命周期不完整

状态：部分未实现，P1。

证据：`ApprovalApi.java` 只有申请、待办、同意和拒绝。没有本人申请历史、撤回、管理员撤销已批准授权、审批转交和到期清理接口。`:56` 待办不排除过期记录，`:74` 决策又拒绝处理过期记录，过期待办可能持续积压。读取只在连接目标数据库之前检查一次白名单和审批。

影响：无法从审批维度撤销一条既有授权；过期待办不可处理；并发撤销期间在途读取缺少返回前校验。24 小时有效期从申请时开始计算，尚需明确是否符合业务授权期限。

验收要求：补齐申请与授权撤回、到期状态和任务清理；增加授权历史；明确有效期起点与在途撤销保证，并用并发场景验证。

### B06 审计完整性和业务变更一致性不足

状态：实现不完整，P1。

证据：`AuditService.java:21` 直接写普通数据表，没有不可篡改校验或外部锚点。审计与告警分两次写入，方法本身无事务。`UsersApi.java`、`DatasourceApi.java`、`AgentTokens.java` 多个变更先落业务数据再写审计，没有事务覆盖。当前运行账号可 UPDATE、DELETE 和 DROP 元数据。

影响：业务变更成功而审计失败时可能向用户报错但数据已改变；审计记录可被同一数据库凭据修改或删除。非法入参和部分 MCP 拒绝也未归入 SQL_READ 指标与告警。

验收要求：业务变更与审计原子提交，审计失败策略明确；拆分最小权限；加入审计完整性或受保护的外部留存证据、保留与清理策略；测试审计库不可用和重试幂等行为。

### B07 数据源连接测试与实际读取条件不一致

状态：实现不完整，P1。

证据：`DatasourceApi.java:67` 使用 REQUIRED 并仅执行 SELECT 1。真实读取在 `ReadApi.java:77`、`:86`、`:98` 分别要求目标主机白名单、VERIFY_IDENTITY 和 SHOW GRANTS 只读权限检查。`:44` 启用数据源没有要求通过这些一致性检查。

影响：连接测试成功并不证明能按实际安全条件读取；写权限账号也可能通过连接测试。

验收要求：测试与运行共用目标连接校验，验证证书身份、目标主机、只读权限和实际授权表；页面准确区分连接成功与可用；验证失败阻止启用。

### B08 当前运行配置没有进入仓库定义的生产模式

状态：配置未完成，P1。

证据：`MysqlProductionGate.java:20` 默认关闭生产模式；本机未设置该标记，当前 Secure Cookie 为 false、绑定所有地址、元数据连接只为 REQUIRED。应用用户仍拥有 ALL PRIVILEGES。

影响：现在是内网直接访问部署，未满足仓库自身定义的生产门禁。该发现不否定本机调试可用性。

验收要求：准备经过验证的生产配置，包括可信 HTTPS 入口、Secure Cookie、MySQL 服务器身份校验与最小权限，并按实际部署方式验证生产门禁和证书更新。TLS 入口可以继续使用 IP 地址，但证书和访问方式要匹配。

### B09 缺少新功能与真实读取的验收证据

状态：验证未完成，P1。

证据：本次 Maven verify 仅执行 8 个工具方法测试。`standalone-mysql.yml:76` 调用登录和基础审批脚本；现有脚本验证了部分 MCP 认证、发现和拒绝行为，但没有成功执行真实目标表读取、策略运行时生效、动态工作流、新监控告警、双会话撤销、并发收权与资源限制。旧 PostgreSQL 安全脚本不覆盖本单体实现。

验收要求：在独立 MySQL 8.4 环境建立成功/拒绝读取、真实只读账号、TLS、审批和字段授权的端到端链路；对新增 API、失败回滚、迁移、负载与浏览器交互做自动验收，保存明确的发布证据。

## 建议实施顺序

1. 先修会话撤销、业务变更与审计一致性、真实读取的权限与资源边界。
2. 接通策略和审批流程的运行链路，补齐授权撤销与到期机制。
3. 完成数据源一致性测试、角色授权、脱敏、Agent 范围和管理界面。
4. 校正监控口径，补齐告警通知、审计查询与生产运维配置。
5. 用独立 MySQL 环境完成整套集成、端到端、浏览器和负载验收，再固定发布制品。

备份与备份恢复按 `STANDALONE_MYSQL.md` 现有范围决定单列排除，不在本报告中重新列为本次必须开发项。多组织、任意 SQL 和写执行也不是只读首发天然必须具备的功能，应根据正式发布范围决定，不能用未实现能力作为产品承诺。
