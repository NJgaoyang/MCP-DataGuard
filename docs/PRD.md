> **实施决议 v0.4**：平台管理库为 PostgreSQL 17，使用同一 `dataguard` 数据库内的 `platform` 和 `flowable` 两个 Schema，独立数据库账号；MySQL/PostgreSQL 仍为首批目标业务数据库插件。本变更不缩减 FR-01～56。

> **文档状态**：需求基线草案（用于产品评审与研发实施，不代表功能已开发）

## 1. 产品概述与边界

### 1.1 产品愿景

MCP DataGuard 允许个人开发者、企业和开源社区免费部署完整功能，通过统一 MCP 工具向 MySQL、PostgreSQL 等数据库发起受控操作，对 SQL 实施身份验证、最小权限授权、SQL 方言解析、风险评估、人工审批、隔离执行、审计追踪。所有功能同源开源，不存在付费解锁、设备绑定、License 文件、激活服务或按 Agent 数量收费。

**“所有人都可用”代表人人可以获取软件、部署实例、参与贡献；不代表任意匿名调用者可以执行目标数据库 SQL。** 生产实例默认开启认证和数据源权限隔离。

### 1.2 用户痛点

| ID | 问题 | 产品响应 |
|---|---|---|
| P-01 | Agent 被提示词诱导进行越权 SQL 操作 | Agent/用户身份绑定、最小权限、数据库账户隔离 |
| P-02 | 普通 SQL 工具缺少写入前审批 | MCP 变更申请 + Flowable 可视化多级审批 |
| P-03 | 多数据库方言复杂，简单正则规则不安全 | 数据库插件、SQL Parser SPI、解析不确定时拒绝 |
| P-04 | 不知道哪个 Agent 执行过什么 | 请求链路审计、可搜索 SQL 记录、审批与执行关联 |
| P-05 | 多套工具重复管理审批和权限 | 统一 Web 管理平台，规则、流程、审计一体化 |
| P-06 | 开源项目常出现核心功能闭源分级 | 全功能开源，支持自部署、贡献和扩展 |

## 3. 核心场景与用户旅程

### 3.1 安全只读查询

Agent 以独立身份调用 `list_datasources`、`get_schema`、`execute_readonly`。服务端验证令牌、组织和数据源权限，解析 SQL、拒绝不可确定副作用、应用行列权限和查询限额，经只读账号执行，输出截断/脱敏并记录审计事件。失败时返回安全错误码，不暴露数据库凭据。

### 3.2 DELETE 人工审批

Agent 调用 `submit_change` 提交参数化 DELETE、理由、数据源。系统完成解析与规则判断，仅在“可以申请”的情况下生成审批单，启动指定版本的 Flowable 流程，返回 `PENDING_APPROVAL` 和工单号。审批人核对 SQL、数据源、风险及影响范围；批准后执行器重新核验 SQL 哈希、授权与环境并执行。Agent 调用 `get_change_status` 获得最终状态。

### 3.3 拒绝与阻断

对于 SQL 注入式多语句、未知方言、高风险无法可靠解析语句、Agent 访问未授权数据源、缺少 WHERE 的生产 DELETE、危险导出/系统过程，默认 `DENY`；审批不能作为技术性禁令的绕过手段。

### 3.4 社区安装与集成

开发者从公开仓库获取源码和 Compose 配置，通过安装向导创建管理员和示例只读数据源，配置 OAuth/OIDC 或本地管理认证，注册 Agent，连接 MCP Client，运行示例查询及审批演示。贡献者可依据 ADR、插件规范和测试契约添加数据库方言插件。

## 5. 组织、身份与 Agent 治理需求

### 5.1 组织、用户和角色（FR-01～04）

- **FR-01 组织空间**：支持创建组织、激活/停用、组织级默认策略。数据库源、Agent、审批模板、审计默认隶属一个组织；所有后端列表、详情、导出均验证资源归属。
- **FR-02 人员身份**：支持本地首次引导管理员；可接入通用 OIDC 身份提供方（Keycloak 为参考实现）。密码必须加盐哈希，支持强密码、登录错误限制、会话撤销；敏感操作要求二次确认。
- **FR-03 角色与数据权限**：系统、组织、数据源、库、表、列以及 MCP 工具授权，默认拒绝，支持角色继承的审计解释但不可越权。
- **FR-04 责任分离**：申请人/Agent 身份与审批人身份分离；有写入权限的独立执行器凭据不对 Web/API/Agent 暴露。

**验收**：跨组织 ID 猜测均返回统一的不可见结果；管理员没有无条件读取全部业务库数据的能力；停用用户或 Agent 后新请求立即失效。

### 5.2 Agent 管理（FR-05～08）

- **FR-05 Agent 注册**：名称、说明、负责人、用途、允许客户端、所属组织、启停状态；Agent ID 服务端唯一生成。
- **FR-06 认证**：OAuth2/OIDC JWT 或受控客户端凭据；绑定 token 的 `iss/aud/sub/exp`，不得相信请求体自报的 Agent ID。
- **FR-07 工具授权**：逐 Agent 配置可见 MCP 工具、数据源集合、只读与变更申请能力、可访问对象范围；管理员可查看有效策略来源。
- **FR-08 安全配额**：请求速率、最大并发、单次返回行数/字节、超时、每日变更申请上限，所有限制为安全用途，无商业额度。

**验收**：Agent A 无法读取 Agent B 的审批单或数据源；撤销令牌、停用 Agent、禁用工具都能阻止后续调用。

## 6. 数据源与多数据库插件（FR-09～13）

- **FR-09 数据源 CRUD**：数据库类型、驱动、环境（开发/测试/生产）、网络端点、库名、SSL/TLS、连接参数、连接超时、负责人及标签。
- **FR-10 凭据安全**：只读凭据和审批执行凭据分别保存/引用，支持环境变量、外部 Secret Provider 或应用加密托管；禁止回显明文。
- **FR-11 连通性及权限检测**：连接测试区分网络、认证、TLS、最小权限不足；展示检查项而不泄露私密值。
- **FR-12 元数据服务**：经授权查看库/Schema/表/列、数据类型、索引和可见对象；可缓存并提供过期机制。
- **FR-13 插件能力声明**：每个数据库公开 `metadata/read/insert/update/delete/ddl/estimate/transaction/masking` 支持等级，未认证能力在 UI 中禁用，禁止“JDBC 可连接 = 安全写入支持”的误判。

**适配路线**：V1.0 完整认证 MySQL、PostgreSQL；SQL Server/Oracle/ClickHouse 作为后续插件。ClickHouse 异步 Mutation 不得直接沿用事务型数据库写入规则。

## 7. MCP 工具与客户端体验（FR-14～18）

- **FR-14 `list_datasources`**：仅返回有权访问的数据源及支持能力，不返回连接串/用户名/密码。
- **FR-15 `get_schema`**：元数据查询支持分页、筛选和可见对象限制；避免暴露敏感字段注释。
- **FR-16 `execute_readonly`**：只接受单条、已确认只读且无副作用的 SQL 与独立参数；返回列、类型、行、截断标记、耗时、请求 ID。
- **FR-17 `check_sql`**：不执行 SQL，返回标准化操作、目标对象、命中规则、风险等级和 `ALLOW/APPROVAL/DENY` 决策；输出不包含对抗绕过的细节。
- **FR-18 `submit_change` / `get_change_status`**：提交待审批 SQL，返回 request/approval ID；查询状态应区分“已审批”和“已执行”；仅本人或授权角色可见。

**行为约束**：每个工具具有稳定 JSON Schema、参数范围和错误码；版本通过协议兼容规范管理。默认不向 Agent 提供 `approve_change`、任意 SQL 执行或管理员管理工具。Streamable HTTP 是首要传输方式；兼容能力按客户端实测发布。

## 8. SQL 安全策略（FR-19～26）

- **FR-19 方言分析**：依据数据库插件调用 ShardingSphere SQL Parser 或专有适配器，生成产品中立的 SQL Security Context；不能解析、不能完整识别时拒绝。
- **FR-20 SQL 操作识别**：SELECT/INSERT/UPDATE/DELETE/DDL/事务/调用、联接、子查询、CTE、结果导出、锁定读取、动态执行等；默认拒绝多语句与未授权过程调用。
- **FR-21 风险规则**：条件支持组织、Agent、环境、数据源、库/表/列、操作类别、WHERE、敏感级别、时间段、预计影响范围等。
- **FR-22 决策顺序**：硬拒绝 > 对象权限拒绝 > 明确允许/审批规则 > 默认拒绝。命中多条时可解释规则来源、顺序、版本；不得被客户端覆盖。
- **FR-23 规则管理**：草稿、验证、模拟执行、发布、回滚、版本差异、变更审计；生产环境规则修改建议复核。
- **FR-24 只读管控**：强制 DB 只读权限、结果行列过滤/脱敏、查询超时、资源配额；不得仅依赖 SQL 前缀或 JDBC `readOnly` 标志。
- **FR-25 影响评估**：支持 Explain/预估，明确标记“估算值”，对于不能可靠限制影响行数的变更不自动执行。
- **FR-26 安全基线**：禁止无 WHERE 生产写入（除受控特批策略）、DROP/TRUNCATE 默认拒绝、危险函数/导出/CALL/多语句/解析异常默认拒绝；经批准不能直接放开数据库账户权限。

**基础策略参考**：SELECT 在完整只读验证后可 ALLOW；INSERT/UPDATE/DELETE 默认 APPROVAL（具备可靠写入能力的数据库）；DDL 默认 DENY 或仅限独立 DBA 管理策略；存储过程、未知 SQL、权限操作默认 DENY。

## 9. Flowable 审批中心（FR-27～33）

- **FR-27 BPMN 模板设计**：集成 bpmn-js 可视化设计器；流程支持用户任务、排他/并行网关、多实例会签、定时器、监听与条件分支；发布前校验审批人绑定、不可到达节点、无审批直通路径。
- **FR-28 模板版本**：草稿/已发布/停用，发布生成固定版本；运行中工单使用提交时绑定的版本，不随新发布静默变化。
- **FR-29 规则关联**：按组织、数据源、环境、风险等级、SQL 类别映射审批模板，支持安全管理员设置默认兜底流程。
- **FR-30 任务中心**：待办、已办、我发起、转办/委托、退回、拒绝、撤回、工单详情，支持意见、附件（安全扫描）和历史轨迹。
- **FR-31 审批一致性**：禁止自批、跨组织审批、角色越权，审批决议受数据库唯一约束/乐观锁保护；审批人对工单不可修改 SQL 快照。
- **FR-32 时效与提醒**：到期提醒、超时升级、超期拒绝或人工处置、审批状态通知（Webhook/邮件可配置）；系统重启不丢待办。
- **FR-33 审批结果联动**：通过后**仅**生成受约束的执行授权任务，拒绝则不执行；显示执行中的独立状态，不能把“流程已通过”标成“SQL 已成功”。

**验收**：任意工单经拒绝、撤回、审批超时、组织权限变化或 SQL 被篡改后均不能执行；未完成所需审批人数量不得启动执行。

## 10. 独立安全执行器（FR-34～38）

- **FR-34 只读执行器**：使用最小 SELECT 权限数据库账号，强制资源约束，捕获失败并输出脱敏结果。
- **FR-35 写入执行器**：独立进程/服务、独立网络权限和凭据；Web/MCP 服务不可读取其写入密钥。
- **FR-36 精确执行授权**：签名或服务端可信引用绑定组织、数据源、目标数据库、SQL 摘要、参数摘要、审批实例版本、申请主体、有效期与执行次数。
- **FR-37 幂等及未知态**：同一批准任务最多自动发起一次有效提交；网络故障导致结果未知时标记 `UNKNOWN` 并人工核对，严禁盲重试 DELETE/INSERT。
- **FR-38 执行回执**：记录执行前校验、开始/完成时间、影响行数、异常、事务状态与审批工单链路；支持取消未开始任务，不承诺中断已提交数据库事务。

**安全目标**：所有写入从 MCP 请求到物理数据库执行必须走“审批且再次检查”的受控路径；数据库凭据和网络 ACL 是最终兜底。

## 11. 审计、监控与告警（FR-39～44）

- **FR-39 请求审计**：记录请求 ID、追踪 ID、时间、Agent 身份、人类发起人（如有）、组织、数据源、SQL 指纹、规则版本、决策、耗时与结果。
- **FR-40 审批审计**：记录工单每次变更、BPMN 任务领取/审批/转办、审批人、理由、规则版本与最终执行关系。
- **FR-41 检索与导出**：按时间、Agent、用户、组织、SQL 类型、数据源、风险、状态、工单 ID 检索与授权导出；分页、脱敏。
- **FR-42 实时监控**：请求 QPS、失败率、P95/P99、工具调用、慢查询、危险 SQL 拦截、审批积压、执行器状态、连接池。
- **FR-43 安全事件告警**：重复拒绝、异常访问、大量失败、可疑查询、执行失败、审批积压，支持 Webhook/邮件；告警去重、静默和恢复。
- **FR-44 防篡改证据**：追加写审计、哈希链/周期签名、外部不可变存储导出接口、时钟与链路关联。说明此为可验证篡改迹象，不宣称单库绝对不可篡改。

**范围说明**：系统只审计经过自身 MCP/REST 安全执行入口的 SQL；直连业务数据库的请求需要数据库原生审计或外部代理补充。

## 12. Web 前端需求（FR-45～48）

### 12.1 信息架构

首页总览 / Agent 管理 / 数据源管理 / 库表权限 / SQL 安全策略 / 策略模拟 / 审批流程设计 / 审批任务中心 / SQL 请求与审计 / 实时监控告警 / 组织用户角色 / 系统设置 / 文档与社区。

### 12.2 界面标准

统一清爽 BI 风格，左侧导航、面包屑、简洁紧凑筛选器、低密度阴影、响应式表格。界面中以明显文字区分“待审批”“审批通过待执行”“执行成功”“执行失败”“执行未知”；危险操作二次确认，SQL 编辑器支持高亮、格式化、只读 diff 与参数展示。

- **FR-45 首页**：总览卡片、趋势、异常 TOP、待审批、最近活动，支持按组织和环境过滤。
- **FR-46 核心工作台**：Agent/数据源/规则/审批/审计的列表、详情、创建、编辑与回滚流程，权限受控。
- **FR-47 实时体验**：审批进度、SQL 监控采用 SSE/WebSocket，断连恢复以服务端真实状态为准。
- **FR-48 可用性**：简体中文优先、预留英文、多浏览器兼容、键盘可访问、移动端至少支持审批查看与处理。

## 13. 开放接口与插件生态（FR-49～51）

- **FR-50 Webhook**：审批创建、任务指派、审批决议、执行结束、策略发布、安全告警；签名、重试、死信与事件 ID 去重。
- **FR-51 插件开发包**：数据库 SPI（连接、元数据、方言、风险规则、只读执行、受控写入、能力申明）、标准测试包、示例插件、版本与兼容性说明。

## 15. 数据库兼容能力矩阵与验收原则

| 数据库 | 元数据 | 安全只读 | 受控 DML | DDL | 首次目标 |
|---|---|---|---|---|---|
| MySQL 8.x | P0 | P0 | P0 | 默认禁止，后续认证 | V1.0 |
| PostgreSQL 16+/指定认证版本 | P0 | P0 | P0 | 默认禁止，后续认证 | V1.0 |
| MariaDB | P1 | P1 | P1，单独测试 | 默认禁止 | V1.x |
| SQL Server | P1 | P1 | P1 | P2 | V1.x |
| Oracle | P1 | P1 | P1 | P2 | V1.x |
| ClickHouse | P1 | P1 | 限定能力；异步变更需专门方案 | 默认禁止 | V1.x |
| TiDB、Doris、StarRocks、Trino、国产数据库 | P2 | P2 | 按库认证 | 默认禁止 | V2.x |

“P0/P1/P2”表示研发优先级而非已实现状态。正式对外发布应记录驱动版本、数据库版本、SQL 语法用例数、安全拒绝覆盖率、写入事务与回滚测试结果。

## 16. 非功能性需求

| 编号 | 类别 | 要求和验收方式 |
|---|---|---|
| NFR-01 | 安全性 | 所有服务端接口验证身份、组织归属和工具权限；敏感配置加密；不得回传数据库密钥 |
| NFR-02 | 可用性 | 数据库/审批引擎不可用时写入默认拒绝；支持服务重启后恢复审批与任务追踪 |
| NFR-03 | 性能 | V1.0 的网关自身 P95 附加处理开销目标 ≤ 100ms（不含目标数据库、网络、人工审批）；以实际压测确认 |
| NFR-04 | 并发 | 基准压测 100 并发只读请求和至少 1,000 已持久化待审批工单；硬件环境公开 |
| NFR-05 | 数据保护 | 支持结果行数上限、输出字节上限、超时与字段脱敏；审计 SQL 参数按策略加密或遮盖 |
| NFR-06 | 恢复 | 定期备份/恢复演练；目标 RPO/RTO 在部署配置中明确，不做未经测量的承诺 |
| NFR-07 | 可观测性 | 关键接口有请求 ID/trace ID、指标、告警；审计可关联 Flowable 任务与数据库执行 |
| NFR-08 | 国际化 | 简体中文优先，支持后续英文；时间使用 UTC 存储及用户时区显示 |
| NFR-09 | 易部署 | 快速开始包含最小资源、安装步骤、首次安全设置、示例查询和常见故障处理 |
| NFR-10 | 开源可复现 | 从源码可构建镜像；公开 CI、依赖锁定、测试数据和 SPDX/SBOM |

## 17. 关键验收测试与发布门槛

| 验收编号 | 场景 | 通过条件 |
|---|---|---|
| AT-01 | 未认证直接请求 `/mcp` | 不得列出或调用受保护工具 |
| AT-02 | Agent 尝试跨组织访问数据源 | 拒绝，审计记录存在，不泄露对象详情 |
| AT-03 | SELECT 中嵌入有副作用/多语句 | 无数据库副作用，返回 DENY |
| AT-04 | PostgreSQL 写入 CTE / SQL Server SELECT INTO | 不得误判为安全只读 |
| AT-05 | 无 WHERE DELETE / 未识别 SQL | 拒绝，不能仅凭审批放行 |
| AT-06 | 已批准后 SQL/参数/目标库变化 | 拒绝执行，保存篡改/失效审计 |
| AT-07 | 申请人尝试审批自己工单 | 拒绝，权限变更不能绕过 |
| AT-08 | 同一批准工单反复回调执行 | 不重复提交写入；未知态走对账 |
| AT-09 | Flowable 重启/网络超时 | 流程可恢复，不产生未授权执行 |
| AT-10 | 数据源写账号被业务网关直接调用 | 物理网络/凭据层隔离，调用失败 |
| AT-11 | 审计导出包含敏感参数 | 未授权用户只能获得脱敏记录 |
| AT-12 | Docker 离线重部署恢复备份 | 配置、流程版本、未完成工单和审计记录一致 |
| AT-13 | 数据库插件解析不完整 | capability 降级/拒绝，不标为生产认证 |
| AT-14 | 禁用 Agent/撤销凭据 | 新请求立即被拒绝且留下审计事件 |
| AT-15 | 开源完整性 | 所有核心模块源码、完整构建方式公开，无授权文件或付费模块依赖 |

**发布硬门槛**：P0 安全用例全部通过，至少 MySQL 与 PostgreSQL 分别通过完整的只读和变更审批链路；安全扫描无未处置的严重风险，能从公开源码复现发行镜像。

## 18. 风险与决策待办

| 风险 | 缓解措施 | 归属 |
|---|---|---|
| SQL Parser 无法充分理解特殊语法 | 严格能力矩阵、黑盒对抗用例、未知即拒绝 | SQL 安全组 |
| 预估影响行数不可靠 | 明示估算、执行前复核、业务库权限兜底、受控事务 | 执行器组 |
| Flowable 任务重试引发重复 DML | 执行 outbox/租约状态机、UNKNOWN 人工对账 | 工作流组 |
| 多租户逻辑隔离不足 | 完整租户资源范围校验与渗透测试，重要实例可独立部署 | 平台安全组 |
| 开源第三方许可不兼容 | 自动许可证扫描 + 专项法律复核，不预打包受限驱动 | 开源治理组 |
| 组件升级版本冲突 | Spring Boot 4 / Spring AI 2 / Flowable 8 组合锁定与集成测试 | 架构组 |
| 过度承诺数据库支持 | 公开分等级兼容列表、每数据库版本认证 | 插件组 |
